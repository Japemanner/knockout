Duplicate Key Error oplossen in Supabase

Project: Knockout  |  Tabel: prive_fin_week  |  Datum: 25 juni 2026

Het probleem

Bij het aanmaken van een nieuw record via het CRUD-tabblad in Knockout verschijnt de volgende foutmelding:

duplicate key value violates unique constraint "prive_fin_week_pkey"

Oorzaak

De primary key-kolom id in de tabel prive_fin_week is een identity column — de database hoort de waarde automatisch in te vullen via een onderliggende sequence (teller).

Het probleem ontstaat wanneer er records met handmatige ID's zijn ingevoerd (bijvoorbeeld via een import of directe SQL-insert). De sequence loopt dan achter op de daadwerkelijk maximale waarde in de tabel. Bij de volgende INSERT genereert de sequence een waarde die al bestaat, wat leidt tot de duplicate key-fout.

Voorbeeld: De hoogste id in de tabel is 47, maar de sequence staat nog op 3. De volgende insert probeert id = 4 te gebruiken, maar die bestaat al → duplicate key violation.

Oplossing

Reset de sequence naar MAX(id) + 1, zodat de automatische teller verdergaat waar de bestaande data ophoudt.

Stap voor stap

  1. Ga naar de Supabase Dashboard van je project (open dashboard)
  2. Open de SQL Editor in het linkermenu
  3. Plak de onderstaande SQL-query in de editor
  4. Klik op Run om de query uit te voeren
  5. Ga terug naar Knockout en probeer opnieuw een record aan te maken — het werkt direct

De SQL-query

SELECT setval( pg_get_serial_sequence('prive_fin_week', 'id'), COALESCE((SELECT MAX(id) FROM prive_fin_week), 0) + 1, false );

Wat doet deze query?

  • pg_get_serial_sequence('prive_fin_week', 'id') — vindt de naam van de sequence die hoort bij de id-kolom
  • SELECT MAX(id) FROM prive_fin_week — zoekt de hoogste bestaande id-waarde in de tabel
  • COALESCE(..., 0) + 1 — als de tabel leeg is, start bij 1; anders max + 1
  • setval(..., false) — de false betekent dat de volgende nextval deze waarde retourneert (niet waarde + 1), dus de eerste nieuwe insert krijgt max + 1

Geverifieerd: Deze oplossing is succesvol toegepast op 25 juni 2026 en loste het probleem direct op.

Werkt dit voor andere tabellen?

Ja. Vervang prive_fin_week door de naam van de betreffende tabel en id door de naam van de primary key-kolom:

SELECT setval( pg_get_serial_sequence('<tabelnaam>', '<pk-kolom>'), COALESCE((SELECT MAX(<pk-kolom>) FROM <tabelnaam>), 0) + 1, false );

Voorkomen in de toekomst

  • Gebruik altijd INSERT zonder expliciete id — laat de identity column het invullen
  • Bij data-imports: gebruik INSERT ... RETURNING id of laat de id weg zodat de database deze automatisch toekent
  • Als je toch handmatige ID's moet invoeren, voer dan direct daarna de setval-query hierboven uit om de sequence te synchroniseren
